# 工作流与限制

1. 扫描源目录建立库存，按修改时间挑选批次，限制本批字节数。
2. 同一源相对路径只归属一个批次；后续即使大小、内容、inode 或修改时间发生变化，批次归属也不变。
3. 固定指纹后创建目标硬链接，不删除源条目。
4. 等待 Syncthing 两端稳定，并读取 Google 相册当前备份状态。
5. 满足整批确认条件后执行相册“释放空间”，等待删除传播。
6. 观察残留目标；只在内容、备份证据和指纹条件全部满足时清理目标条目。
7. 记录删除来源、执行意图、阶段耗时和批次报告，发送汇总。

Google 相册没有本工具可直接使用的官方备份完成 API，因此本工具通过 Android UI 读取备份状态。应用语言和界面变化可能导致状态无法识别，此时应暂停处理，不能用“已经传到手机”或“手机文件不见了”代替云端备份证明。目前识别中文和英文状态。

“释放空间”是 Google 相册的全局操作，可能释放本批之外、此前已备份的手机内容，不是逐批精确删除 API。请使用专用手机和专用同步目录，并确保理解双向删除传播。

Syncthing 100% 只是整个共享文件夹的传输状态，不能证明每张照片已备份到 Google。错误或离线时不授权清理。文件在确认后变化时必须重新核查，不能用旧指纹删除。

手动清理入口 `controller/cleanup_target.py` 默认只预览；`--execute` 才执行。控制器长期运行时会自动执行工作流，必须先配置好安全边界，并完成小批量验证。

网页只提供读取功能，没有远程删除接口。文件路径、批次和电量属于私有信息，仍需设置访问控制。手机电量、充电状态和快捷入口只用于展示，不影响任何清理条件。

删除归因分为 manual、syncthing、unknown。仅凭文件缺失不能断言由手机端删除；无法确认的结果保留 unknown。进程退出、数据库重连、ADB 重启或重试都不能绕过目标目录保护。

## 文件时间显示

文件明细列表与详情优先使用 EXIF DateTimeOriginal 拍摄时间，保留相机记录的本地时间及可用时区，不把无时区时间转换为 UTC。支持 Pillow 图片格式及 HEIC/HEIF。无有效拍摄时间时使用源文件系统提供的创建时间（birth time），页面标注“创建时间”；两者均不可用则显示“未记录”。Unix ctime 是元数据变更时间，mtime 是修改时间，均不冒充创建或拍摄时间。NFS 等文件系统可能不提供创建时间。

控制器启动以增量迁移添加 nullable 库存字段，并在下次源扫描补齐已有记录；按大小、mtime、dev、inode 缓存元数据，无变化不重复解码。历史已离线的源文件不能补读，已有时间随库存记录保留。看板依旧只查询数据库，不挂载照片。此时间仅展示，不参与批次或清理判定。
